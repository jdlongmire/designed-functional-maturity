# WP-005: DFM Programme Foundation and Repository Refactor

**Status:** Executed — baseline  
**Purpose:** Convert the repository from a paper staging area into the canonical home of the Designed Functional Maturity research programme.

## Problem

The repository had no root README and exposed almost none of the programme's accumulated model structure at entry. The root consisted only of artifact directories. The principal draft also predates WP-002 and WP-004 refinements and therefore cannot serve as the sole description of current DFM.

## Executed scope

1. Add a substantive root README.
2. Add a canonical research-programme charter.
3. Add a research roadmap.
4. Surface the hard core, positive and negative heuristics, initialization formalism, Reconstruction Argument, radiogenic model, predictions, severe tests, and current explanatory burdens.
5. Make the relationship between DFM and BWM explicit.
6. Identify the current synthesis draft as a working artifact rather than silently treating it as canonical.
7. Establish quantitative U-Pb concordance as the next technical gate.

## Acceptance criteria

- A first-time reader can identify what DFM is from the repository landing page.
- The difference between functional maturity and traversed history is explicit.
- The repository states what DFM affirms, what it does not claim, and what could count against its auxiliaries.
- Radiogenic heat, coherent initialization, and orderly-marker treatment are visible at programme level.
- The roadmap exposes unresolved work rather than implying completion.
- Existing work packages are navigable from the root.

## Result

Baseline repository foundation completed. Follow-on work should revise the older synthesis draft against the now-canonical programme charter and develop the quantitative severe-test artifacts.
